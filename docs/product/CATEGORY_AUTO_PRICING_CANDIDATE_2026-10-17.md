# Automatic Category Pricing Candidate

Owner resolution: Auto is the default for new POS sessions without a saved choice. Retail and Dealer remain manual; existing explicit Wholesale remains available for compatibility. A saved manual selection is preserved. Auto never silently selects Dealer.

An authorized catalog manager explicitly binds a pricing group to a real tenant category in Back Office pricing. Existing groups are not inferred from names or automatically backfilled. Shared groups retain their existing shared threshold semantics. Auto uses the active reseller's assigned Wholesale list, otherwise the active default Wholesale list. No applicable list or no explicit category binding means retail, not an invented discount.

For each cart category, add exact thousandth quantities across all products/sizes, including items without a Wholesale entry. Different categories never contribute. Each configured line qualifies only when its group's bound category matches its product category and the combined category quantity reaches that group's threshold. It uses its own configured unit price. Unpriced/mismatched/below-minimum lines remain retail. Any qualifying Wholesale line requires an active reseller; the UI prompts and the database rejects completion without one.

Both preview and database round each line once to centavos, then add the rounded lines. Preview uses BigInt; PostgreSQL uses numeric. Back Office input rejects extra decimal places, exponent notation, malformed and unsafe values instead of silently rounding a threshold. Quantity removal recomputes eligibility. Prices/thresholds are resolved again by the server at completion; a changed total cannot settle against a stale payment allocation.

New sale-line snapshots record actual pricing type, manual/category basis, category/group/list IDs, qualifying quantity and threshold. Existing historical lines remain NULL/unclassified; no history or stock is rewritten. Mixed receipts may have a Wholesale header while retail-fallback lines retain their actual Retail label and original price. Refunds continue using original line unit prices. Inventory remains the same branch-variant balance and append-only movement ledger.

Ordered migration: `20261017070933_pos_category_auto_pricing`, after the reference validator and Sales branch correction. The reference validator still wraps the private priced-sale core; Auto cannot bypass reference requirements, permissions, cutover, stock, register, cash, loyalty, audit or idempotency checks. Same-key completed retry returns the original result before reevaluating changed pricing settings.
